# AI + 低代码平台

**用可视化设计和 AI，把业务想法直接变成能上线运行的系统。** 本平台面向没有专职开发团队、或开发排期永远不够用的中小团队：业务人员自己动手，就能搭出带数据管理、审批流程、权限控制和会员体系的完整应用——企业官网、内部 OA、商城、论坛、客服系统都可以长在同一个平台上。它解决的是"业务系统从零开发太慢、改一次等一轮排期"的问题；高并发交易、支付资金清算这类场景不在它的能力范围内（支付对接第三方服务完成），财务等强合规专用软件也请交给专业产品。

## 平台技术栈

平台全栈使用 TypeScript：前端、服务端与边缘网关共用同一套设计结构定义（版本化发布的 `@naka1205/schema` 契约包），应用在设计、预览、上线三个阶段由同一套渲染器呈现，所见即所得。

| 层 | 技术 |
| --- | --- |
| 开发语言 | TypeScript（前端、服务端、边缘网关全栈统一） |
| 前端应用 | React 18 + Vite 6 + Ant Design 5（运行端、管理台、设计台三个应用） |
| 页面渲染 | 自研页面渲染器 + 共享组件库（设计预览与正式运行共用同一套渲染逻辑） |
| 流程设计 | React Flow（流程图节点编排） |
| 边缘网关 | Cloudflare Workers + Hono（请求转发、公开内容缓存、源站不可用时降级浏览） |
| 前端托管 | Cloudflare Pages；静态快照分发用 Cloudflare R2，降级缓存用 Cloudflare KV |
| 服务端 | Node.js + Hono（业务接口与智能体两个独立服务，Docker 容器运行） |
| 数据库 | PostgreSQL 18 + pgvector（业务数据与知识库向量检索同库）；Redis（运行时缓存） |
| 数据校验 | Zod（设计结构与接口入参的模式校验） |
| AI 接入 | OpenAI 兼容接口双通道（对话模型与向量模型分别配置，向量维度可配） |
| 移动端 | Capacitor 8（同一套 Web 应用打包为 Android / iOS App） |
| 工程与交付 | pnpm monorepo；GitHub Actions 构建 Docker 镜像并发布到 GHCR，服务器侧 Docker 编排部署 |

## 它能帮你做什么

很多团队的业务还跑在 Excel、微信群和纸质单据上：数据对不上、审批靠催、想查个历史记录要翻半天。买现成软件，流程对不上自己的做法；找外包开发，贵、慢、上线后改一个小字段又要重新谈价排期。

这个平台给的是第三条路：**你自己搭**。不需要会写代码——数据表用表单定义，页面用设计器拼，审批流程拖出节点连起来，权限勾选配置。搭好点一次发布，应用立刻上线，员工打开浏览器（或手机 App）就能用。更进一步，平台内置了 AI：向导会一步步帮你把应用生成出来，日常使用时智能助手能直接帮你查数据、起草单据、回答客户咨询。

已经在平台上真实运行的应用包括：企业官网（内容发布 + 访客咨询）、星桥商城、星桥论坛、协同办公 OA（请假、报销、用印、会议室、入职等十余类单据审批）、物资管理（采购—入库—领用全链路）、供应商服务中心。

## 从想法到上线的五步

1. **选一个领域模板**：内容、商城、论坛、客服、协同办公等模板自带数据结构和整套页面，选完应用就能用；也可以从空白开始完全自由搭建。
2. **按自己的业务调整**：加字段、改页面、调审批流程和权限，全部可视化完成，AI 向导和设计助手可以代劳大部分。
3. **发布**：设计先存在草稿里，确认无误点发布即刻上线；发错了可以回滚到任何一个历史版本。
4. **投入使用**：员工在应用里办业务、走审批；客户和会员从官网、商城、论坛访问；手机上可以用浏览器，也可以装成 App。
5. **日常运营**：在管理台里看数据、改数据、管人员和权限、查审计记录，AI 运营助手帮你汇总和分析。

## 功能一览

### 应用搭建

- **领域模板开箱即用**：每个模板是一个完整应用的蓝图——数据表、页面、审批流程、角色权限成套配好。协同办公模板还提供"样板库"，请假、报销、付款、入职等十余种单据整套选用，不用一个个从零画。
- **数据建模**：用表单定义业务对象和字段：文本、数字、日期、选项、附件、富文本、关联其他对象、主子表（一张单据带多行明细）等一应俱全，带校验规则和默认值。
- **页面设计器**：列表页、表单页开箱生成，也能自由拼装不绑定数据的自定义页面（比如活动落地页、数据看板）；菜单跟着页面走；同一个页面可以单独再设计一份手机版布局。
- **流程设计器**：把审批流程画出来——节点、负责角色、每一步单据变成什么状态、驳回后怎么办，保存即生效，单据状态自动跟流程联动。
- **权限设计**：细到"哪个角色能看到哪个菜单、能操作哪类单据、只能看自己部门的数据、哪些字段只读、哪些字段要脱敏"，全部勾选配置，服务端严格执行。
- **AI 向导**：从零建应用时，向导像顾问一样逐个环节提问并生成方案——先定数据模型，再生成页面、流程、权限——每一步你确认了才算数，生成的结果和手工搭的完全一样、随时可改。
- **AI 设计助手**：搭建过程中随时对话求助，让它加个字段、调整页面、补一条流程，动作以提案形式出现，你点头才生效。
- **模板自带内容受保护**：模板的固有结构只能增加不能误删，防止误操作把应用骨架拆坏；你自己加的部分可以自由增删。

### 日常使用（员工侧）

- **多个应用各管各的**：每个应用有独立入口、独立菜单、独立数据，互不干扰；在建应用的数量没有硬性限制。
- **业务办理**：按设计生成的列表和表单开单、查单、改单，支持多条件筛选、排序、分页、按字段汇总统计，主子表单据（如采购单带明细行）编辑顺手，附件直接上传。
- **待办中心**：所有应用的待办汇到一处提醒：待我审批、我发起的、已处理、通知四个视图；能发起新流程、催办、看每张单据走到哪一步的完整时间线。
- **审批**：多级审批、按角色自动派给对应的人，通过和驳回都会自动回写单据状态，全过程留痕，随时可查可回放。

### 对外经营

- **企业官网与内容发布**：栏目、文章、公开页面一站管理，换主题就能整站换装，页面生成静态副本加载更快；官网上的留言、报名等表单提交会自动变成后台的一条业务数据，不用再人工搬运。
- **商城**：商品管理、购物车、结算下单、订单处理齐全，支付接第三方支付服务完成收款，平台不经手资金，适合中小规模经营。
- **论坛社区**：版块、发帖、回复、会员互动，配套版主管理（置顶、加精、违规处理）；版主从普通会员中任命，在社区前台行使权限，不需要给他开后台账号。
- **在线客服**：网站上的咨询浮窗，访客提问先由 AI 基于你的知识库回答，答不上来或访客要求时自动转成工单，客服人员在管理台接单处理，咨询量、响应情况有统计。

### 会员体系

- **注册登录**：带图形验证码防机器刷注册；会员可以在手机和电脑上使用。
- **一套会员走多个应用**：官网、商城、论坛可以共用同一套会员——注册一次，处处登录，不用来回重复注册。
- **统一账户中心**：会员身份集中在一个账户中心管理，各应用通过单点登录接入，安全又省事。
- **会员也能有角色**：版主这类身份直接在会员体系里任命和收回，与员工账号完全分开、互不影响。

### 智能助手与知识库

- **员工助手**：在应用界面里用大白话提问——"上个月华东区的报销总额多少""帮我起草一张请假单"——它能查数据、做汇总、起草单据、发起流程。凡是会改数据的动作，它都先把草稿给你看，你确认后才真正执行；它能看到的数据严格等于你本人的权限，问到越界的内容会明确拒绝并告诉你该找谁。
- **访客客服助手**：7×24 在线答客，答案只来自你审核过的知识库，不会信口开河。
- **运营助手**：管理者在管理台里对话式查运营数据、看待办、做汇总。
- **知识库**：把产品手册、政策文档、常见问题放进知识库，AI 按语义理解问题找答案；内容先审后发，待审核的资料绝不会被提前引用。
- **用量看得见**：AI 的每一次调用都按用途分别计量（搭建、用助手、客服各算各的），管理台可查，超出预算自动熔断，不会失控烧钱。

### 管理与运营（管理台）

- **一个应用一个管理空间**：进入管理台就身处某个应用，菜单和数据都只属于它，不会把几个应用的数据混在一起看；总管理员可以切换应用，也能看到全局汇总数字。
- **每类应用有专属管理页**：文章、订单、工单、会员等都有针对性的管理界面，不用在通用表格里凑合。
- **数据能直改，全程留痕**：运营中发现数据错了，管理人员可以在管理台直接修正；谁在什么时候改了什么，审计日志记得清清楚楚，还能按单条记录回放全过程。
- **人员与授权**：管理平台用户和角色；可以把某个应用的日常运营授权给指定同事，对方登录后只能看到被授权的那一个应用。
- **配置集中管理**：AI 模型接入、支付参数、邮件发送等平台级设置都在配置中心维护，不用改代码。
- **域名与主题**：给应用绑定自己的域名；指定一个主应用占据官网首页；主题分电脑版和手机版两份分别设置，可以用领域提供的主题，也可以上传自己应用专属的主题，预览满意再启用。

### 移动端

- **手机浏览器直接可用**：页面有专门的移动布局时用移动版，没有时自动适配窄屏。
- **可装成 App**：同一套应用可以打包成 Android 和 iOS 应用发布，支持扫码、拍照、调用手机能力，底部导航等界面元素会自动避开手机的安全区。

### 安全与可靠

- **权限不是摆设**：菜单看不见只是第一层，接口层面的数据权限和字段脱敏在服务端统一执行，绕过界面也拿不到不该拿的数据。
- **公开内容零泄漏**：对外只展示已发布内容，未发布的草稿即使知道链接地址也打不开。
- **源站维护不宕站**：服务器短暂不可用时，已发布的公开页面由网络边缘的副本继续提供浏览，恢复后自动回到实时数据。
- **数据在自己手里**：全部业务数据保存在自有服务器的数据库中，云端只放展示用的副本；将来更换云服务账号，重新部署前端即可，业务数据不受影响。

## 部署方式

平台分两处部署协同工作：**前端应用与访问网关部署在 Cloudflare**，就近为各地用户提供访问；**业务服务与数据库部署在自有服务器**（Docker 方式运行），数据始终留在自己服务器上。访问入口按应用分配：主应用使用平台默认域名， 其他应用绑定自有域名或使用默认域名下的专属路径。提供三个使用入口：

| 入口 | 给谁用 | 做什么 |
| --- | --- | --- |
| 应用运行端 | 员工、会员、访客 | 办业务、走审批、逛官网/商城/论坛、咨询客服 |
| 管理台 | 管理员、运营人员 | 管应用、管数据、管人员、看审计与统计（设计器也集成在管理台内） |
| 设计台 | 应用搭建者 | 独立的设计环境，与管理台内集成的设计器能力相同 |

## 本仓库包含什么

本仓库是平台部署在 Cloudflare 上的部分：三个前端应用与统一访问网关，与平台的服务器端仓库 `lcdp-platform` 配套发布。

| 目录 | 内容 |
| --- | --- |
| `apps/runtime` | 应用运行端：业务办理、待办中心、智能助手、客服浮窗 |
| `apps/admin` | 管理台：运营管理与集成的设计器 |
| `apps/studio` | 设计台：独立的应用设计环境 |
| `packages/renderer` | 页面渲染器：把设计好的页面结构渲染成真实界面，设计预览与正式运行共用同一套 |
| `packages/ui` | 共享界面组件库 |
| `src` | 统一访问网关：请求转发与源站不可用时的降级浏览 |

本地运行：

```bash
pnpm install
pnpm --filter @lcdp/runtime dev   # 本地起单个前端
pnpm dev                          # 本地起网关（wrangler dev）
```
